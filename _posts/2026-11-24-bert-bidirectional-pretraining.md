## 한 줄 요약

BERT는 문장 속 단어의 15%를 골라 가린 뒤 앞뒤 문맥을 모두 보고 맞히게 하는 방식으로 Transformer 인코더를 사전학습합니다. 이렇게 만든 모델 하나에 출력층만 바꿔 붙이면 분류, 문장 쌍 판단, 질의응답을 모두 풀 수 있습니다. 이 논문 이후 "큰 말뭉치로 사전학습하고, 과제별 데이터로 짧게 미세조정한다"가 NLP의 기본 작업 방식이 됐습니다.

## 배경: 어떤 문제를 풀려는가

이 글은 커리큘럼 언어 트랙의 첫 번째 글입니다. 공통 기초 트랙의 [Transformer](/2026/11/23/transformer-attention-is-all-you-need/) 글을 먼저 읽어 두면 BERT의 몸체가 그 글의 인코더 그대로라는 점을 바로 알 수 있습니다.

2018년에도 사전학습한 언어 표현을 옮겨 쓰는 방식은 두 갈래였습니다(1절). ELMo는 사전학습 모델의 벡터를 과제별 모델의 입력 특징으로 붙였고, OpenAI GPT는 사전학습한 모델 전체를 과제 데이터로 조금 더 학습했습니다.

저자들이 짚은 문제는 둘 다 한 방향 언어 모델이라는 점입니다. GPT는 다음 단어를 예측하므로 각 단어가 자기 왼쪽만 봅니다. ELMo는 왼쪽→오른쪽, 오른쪽→왼쪽 모델을 따로 학습해 이어 붙일 뿐, 한 층 안에서 양쪽을 동시에 보지는 않습니다.

"그 은행은 강가에 있다"와 "그 은행에 적금을 들었다"에서 "은행"의 뜻은 뒤의 단어가 정합니다. 왼쪽만 보는 모델은 그 단서를 가질 수 없습니다.

그냥 양방향으로 다음 단어를 예측하게 하면 여러 층을 거치며 각 단어가 간접적으로 자기 자신을 보게 되어 답을 베낍니다. BERT의 핵심은 이 문제를 피하는 학습 과제를 새로 만든 데 있습니다.

## 핵심 아이디어

### 구조: Transformer 인코더만 쓴다

BERT는 Transformer의 인코더 층만 쌓습니다(3절). 디코더의 마스크가 없으므로 모든 단어가 문장 전체를 봅니다. 크기는 두 가지입니다.

| 모델 | 층 수 | 은닉 차원 | 헤드 수 | 파라미터 |
|---|---|---|---|---|
| BERT-BASE | 12 | 768 | 12 | 1억 1,000만 |
| BERT-LARGE | 24 | 1,024 | 16 | 3억 4,000만 |

BASE는 GPT와 비교하려고 일부러 GPT와 같은 크기로 맞췄습니다.

입력은 3만 개 어휘의 WordPiece 토큰입니다. 맨 앞에 `[CLS]`를 두고, 두 문장 사이에 `[SEP]`를 둡니다. 입력 벡터는 토큰 임베딩, 몇 번째 문장인지 알려 주는 세그먼트 임베딩, 위치 임베딩의 합입니다. 분류 과제에서는 `[CLS]` 자리의 마지막 은닉 벡터를 문장 전체의 요약으로 씁니다.

### 과제 1: 가려진 단어 맞히기(MLM)

각 시퀀스에서 토큰의 15%를 무작위로 고르고, 고른 자리의 원래 토큰을 맞히게 합니다(3.1절). 손실은 고른 자리에서만 계산합니다.

`L_MLM = - Σ_{i ∈ M} log P(x_i | x̃)`

- `M`: 무작위로 고른 위치의 집합(전체의 15%)
- `x̃`: 고른 위치를 바꿔 놓은 입력
- `P(x_i | x̃)`: 바뀐 입력 전체, 즉 양쪽 문맥을 보고 원래 토큰을 맞힐 확률

정답 토큰이 입력에서 지워져 있으니 양방향으로 봐도 답을 베낄 수 없습니다. 이것이 깊은 양방향 학습을 가능하게 한 열쇠입니다.

문제는 `[MASK]`가 미세조정 때는 나오지 않는다는 점입니다. 이 차이를 줄이려고 고른 토큰의 80%만 `[MASK]`로, 10%는 무작위 토큰으로 바꾸고, 10%는 그대로 둡니다.

가상의 숫자로 따라가 보겠습니다. 200토큰짜리 문장이라면 15%인 30개 위치를 고릅니다. 그중 24개는 `[MASK]`, 3개는 엉뚱한 단어, 3개는 원래 단어 그대로입니다. 모델은 어느 자리가 바뀌었는지 모르므로, 멀쩡해 보이는 단어에 대해서도 문맥과 맞는지 따져 보는 표현을 만들어야 합니다.

```python
def make_mlm_example(tokens, vocab, mask_rate=0.15):
    labels = [IGNORE] * len(tokens)            # 손실을 계산하지 않는 자리
    for i, tok in enumerate(tokens):
        if tok in (CLS, SEP, PAD) or random() >= mask_rate:
            continue
        labels[i] = tok                        # 원래 토큰이 정답
        r = random()
        if r < 0.8:   tokens[i] = MASK         # 80%: [MASK]
        elif r < 0.9: tokens[i] = choice(vocab) # 10%: 무작위 토큰
        # 나머지 10%: 그대로 둔다
    return tokens, labels
```

### 과제 2: 다음 문장 맞히기(NSP)

두 문장의 관계를 배우도록, 문장 A 뒤에 절반은 실제 다음 문장을, 절반은 무작위 문장을 붙이고 `[CLS]` 벡터로 구분하게 합니다(3.1절). 최종 모델의 정확도는 97~98%였습니다.

데이터는 BooksCorpus(8억 단어)와 영어 위키백과(25억 단어)입니다. 긴 연속 구간을 뽑으려면 문장을 뒤섞은 말뭉치가 아닌 문서 단위 말뭉치가 필요합니다.

### 미세조정: 출력층 하나만 바꾼다

사전학습이 끝나면 과제에 맞게 입력을 넣고 출력층만 붙입니다(3.2절, 4절).

- **문장 하나나 문장 쌍 분류**: `[CLS]` 벡터에 분류층을 붙입니다.
- **질의응답**: 질문을 A, 지문을 B로 넣습니다. 새로 배우는 것은 시작 벡터 `S`와 끝 벡터 `E` 두 개뿐입니다.

질의응답의 답 구간 점수는 다음과 같습니다(4.2절).

`score(i, j) = S·T_i + E·T_j  (단, j ≥ i)`

`T_i`는 지문 i번째 토큰의 마지막 은닉 벡터입니다. 앞 항은 i가 답의 시작일 만한 정도, 뒷 항은 j가 답의 끝일 만한 정도입니다.

가상의 숫자로 보겠습니다. 다섯 토큰짜리 지문에서 `S·T`가 [1.0, 3.0, 0.5, 0.2, -1.0], `E·T`가 [2.8, 0.4, 1.5, 1.0, 0.3]이라고 합시다. 시작과 끝을 따로 고르면 시작은 2번(3.0), 끝은 1번(2.8)이 되어 끝이 시작보다 앞서는 말이 안 되는 답이 나옵니다. `j ≥ i` 조건 안에서 찾으면 (2, 3)이 3.0 + 1.5 = 4.5로 가장 높습니다. (1, 1)은 3.8, (2, 4)는 4.0입니다.

답이 없을 수도 있는 SQuAD 2.0에서는 `[CLS]` 자리를 "답 없음"으로 씁니다(4.3절). 가장 좋은 구간 점수가 `s_null + τ`(`s_null = S·C + E·C`)보다 클 때만 답을 냅니다. 위 예에서 `s_null`이 4.0, `τ`가 0.3이면 4.5 > 4.3이므로 답을 냅니다.

## 실험 결과

### 사전학습 설정

부록 A.2 기준입니다.

| 항목 | 설정 |
|---|---|
| 배치 | 256 시퀀스 × 512 토큰 = 128,000 토큰 |
| 스텝 | 100만 |
| 최적화 | Adam, 학습률 1e-4, 처음 1만 스텝 워밍업 후 선형 감소 |
| 시퀀스 길이 | 90% 스텝은 128, 마지막 10%는 512 |
| 장비 | BASE는 Cloud TPU 4대(칩 16개), LARGE는 16대(칩 64개), 각 4일 |

어텐션 비용이 길이의 제곱이라, 대부분 짧게 학습하고 마지막에만 길게 학습해 위치 임베딩을 익힙니다.

### 주요 벤치마크

GLUE 테스트 세트 결과입니다(표 1, 평균은 WNLI 제외).

| 모델 | MNLI-m | QNLI | CoLA | RTE | 평균 |
|---|---|---|---|---|---|
| 이전 최고(GPT 이전) | 80.6 | 82.3 | 35.0 | 61.7 | 74.0 |
| OpenAI GPT | 82.1 | 87.4 | 45.4 | 56.0 | 75.1 |
| BERT-BASE | 84.6 | 90.5 | 52.1 | 66.4 | 79.6 |
| BERT-LARGE | 86.7 | 92.7 | 60.5 | 70.1 | 82.1 |

- 같은 크기의 GPT보다 BASE의 평균이 4.5점 높습니다. 구조가 거의 같으니 차이는 주로 양방향 학습에서 온다고 볼 수 있습니다(데이터 차이도 있습니다).
- 학습 데이터가 2,500개뿐인 RTE에서도 LARGE가 BASE보다 3.7점 높습니다.
- SQuAD 1.1 테스트 F1은 LARGE 앙상블 93.2(표 2), SQuAD 2.0은 단일 모델 83.1로 이전 최고보다 5.1점 높았습니다(표 3).

### 무엇을 빼면 무너지는가

BASE 크기로 사전학습 과제를 바꿔 본 결과입니다(표 5, 개발 세트).

| 설정 | MNLI-m | QNLI | MRPC | SQuAD F1 |
|---|---|---|---|---|
| BERT-BASE | 84.4 | 88.4 | 86.7 | 88.5 |
| NSP 제거 | 83.9 | 84.9 | 86.5 | 87.9 |
| 왼쪽→오른쪽 + NSP 제거 | 82.1 | 84.3 | 77.5 | 77.8 |
| 위에 BiLSTM 추가 | 82.1 | 84.1 | 75.7 | 84.9 |

- 한 방향으로만 학습하면 SQuAD F1이 10.7점 떨어집니다. 토큰마다 오른쪽 문맥이 없기 때문입니다.
- 그 위에 BiLSTM을 얹으면 SQuAD는 일부 회복하지만 GLUE는 오히려 나빠집니다. 양방향성은 사후에 붙이기보다 사전학습에서 깊게 배우는 쪽이 낫습니다.
- NSP를 빼면 QNLI가 3.5점 떨어졌습니다.

모델 크기 실험(표 6)에서는 키울수록 세 과제가 모두 올랐습니다. 학습 데이터가 3,600개뿐인 MRPC도 3층 79.8에서 24층 87.8이 됩니다.

마스킹 방식 실험(부록 C.2, 표 8)에서 80/10/10 규칙과 전부 `[MASK]`로 바꾸는 방식은 미세조정 MNLI가 84.2와 84.3으로 비슷했지만, 특징 추출 방식 NER은 94.9와 94.0으로 벌어졌습니다. 불일치 문제는 사전학습 표현을 그대로 꺼내 쓸 때 드러납니다.

특징만 뽑아 써도 꽤 됩니다(5.3절, 표 7). CoNLL-2003 개체명 인식 개발 세트에서 위쪽 4개 층을 이어 붙이면 F1 96.1로, 미세조정한 BASE(96.4)와 0.3점 차이입니다.

## 한계

저자들이 직접 밝히거나 본문에서 드러나는 한계는 다음과 같습니다.

- **사전학습과 미세조정의 불일치**: `[MASK]`는 미세조정 때 나오지 않습니다. 80/10/10 규칙은 이를 줄이는 장치일 뿐 없애지는 못합니다(3.1절).
- **학습 신호가 적습니다**: 배치마다 15% 위치에서만 손실이 나옵니다. 128,000 토큰짜리 배치라면 예측은 약 19,200개로, 모든 토큰을 예측하는 왼쪽→오른쪽 모델의 약 7분의 1입니다. 부록 C.1은 MLM이 왼쪽→오른쪽 모델보다 조금 느리게 수렴하지만 정확도는 거의 처음부터 앞선다고 보고합니다.
- **생성과 긴 입력**: 인코더만 있어 문장을 이어 쓰지 못하고, 길이 512까지만 사전학습해 긴 문서는 잘라 넣어야 합니다.

이후 연구가 이 한계를 다뤘습니다. RoBERTa(2019)는 NSP를 빼도 성능이 같거나 조금 낫다는 것을 보이고, 마스킹을 매번 새로 뽑으며 160GB가 넘는 데이터로 더 오래 학습했습니다. ELECTRA(2020)는 모든 토큰에 대해 바꿔치기 여부를 판별하게 해 15% 문제를 풀었고, RoBERTa와 XLNet의 4분의 1 미만 연산으로 GLUE에서 비슷한 성능을 냈습니다. 2024년 12월의 ModernBERT는 문맥을 8,192 토큰으로 늘렸습니다. 생성 쪽은 커리큘럼 다음 글인 T5(모든 과제를 텍스트 생성으로 통일)와 GPT-3(디코더만 키워 미세조정 없이 과제 풀기)가 이어받습니다.

## 실무에서 가져갈 점

- **지금도 검색과 분류의 주력입니다.** Google은 2019년 10월 미국 영어 검색 10건 중 1건에 BERT를 적용한다고 발표했고, Hugging Face는 2024년 12월 BERT가 허브에서 두 번째로 많이 내려받는 모델(월 6,800만 회 이상)이라고 밝혔습니다. RAG의 임베딩과 재정렬, 콘텐츠 분류에 이 계열 인코더가 널리 쓰입니다.
- **구간 예측에서는 `j ≥ i` 조건을 지키세요.** 시작과 끝을 따로 argmax로 고르면 위의 예처럼 끝이 시작보다 앞선 답이 나옵니다. 최대 답 길이도 함께 제한하는 것이 보통입니다.
- **쪼개진 단어의 라벨에 주의하세요.** 개체명 인식에서 논문은 단어의 첫 하위 토큰 표현만 분류에 씁니다(5.3절). 나머지 하위 토큰까지 라벨을 붙이면 평가 기준과 어긋납니다.
- **작은 데이터는 재시도가 필요합니다.** 논문도 작은 데이터셋에서 LARGE 미세조정이 불안정해 시드를 바꿔 여러 번 돌리고 개발 세트로 골랐습니다(4.1절).
