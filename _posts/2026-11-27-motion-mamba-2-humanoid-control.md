## 한 줄 요약

휴머노이드 동작을 2.08초 창 단위로 이어 생성하는 확산 모델입니다. 가까운 과거는 어텐션 캐시로, 먼 과거는 Mamba 상태와 기억 슬롯으로 기억하고, 확정된 창만 기억에 반영합니다. 그 결과 39.52초 생성에서 목표 지점 오차가 비교 모델 중 가장 낮았고, 실제 Unitree G1에서 100번 중 94번 과제를 끝까지 수행했습니다.

## 배경: 어떤 문제를 풀려는가

휴머노이드는 "걷다가 손을 흔들고, 3미터 앞에서 멈춰"처럼 중간에 바뀌는 지시를 따라 수십 초씩 움직여야 합니다. 최근 방식은 동작을 짧은 창으로 나눠, 앞 창을 조건으로 다음 창을 확산 모델로 만듭니다. [WaveNet](/2026/11/26/wavenet-raw-audio/)이 소리를 한 샘플씩 이어 만든 것과 같은 자기회귀 구조이고, 단위가 창이라는 점만 다릅니다.

여기서 두 가지가 막힙니다(I절). 하나는 기억입니다. [Transformer](/2026/11/23/transformer-attention-is-all-you-need/)식 어텐션 캐시는 길이를 제한하면 오래된 동작을 잊고, 제한하지 않으면 계속 커집니다. 다른 하나는 속도로, 창마다 노이즈 제거를 여러 번 반복해야 합니다.

이 논문은 저자들의 ECCV 2024 논문 Motion Mamba를 확장했고, 뼈대는 ARDY의 루트-몸통 분해를 따릅니다. Mamba와 확산 모델(DDPM, DDIM)은 커리큘럼에서 따로 다룰 예정이라, 여기서는 Mamba를 "입력을 고정 크기 상태에 누적하는 순환 모델"로 이해하면 충분합니다.

## 핵심 아이디어

### 루트 먼저, 몸통은 그다음

로봇 동작을 루트(골반의 위치와 방향)와 몸통(관절 자세)으로 나눕니다(IV-A, IV-B절). 노이즈 제거의 매 단계에서 루트 모델이 먼저 루트를 예측하고, 몸통 모델은 그 예측을 조건으로 받아 관절 자세를 예측합니다. 두 모델의 파라미터와 기억은 따로입니다. 목표 지점 도달은 주로 루트의 일이라 위치 제어가 쉬워집니다.

### 세 겹의 기억

각 층은 서로 다른 시간 범위를 맡는 기억 세 가지를 씁니다(IV-B, IV-C절).

| 기억 | 범위 | 크기 |
|---|---|---|
| 어텐션 캐시 | 최근 4개 창(208프레임, 8.32초) | 고정, 오래된 창부터 버림 |
| Mamba 상태 | 처음부터 지금까지 | 시퀀스 길이와 무관 |
| PCM 슬롯 | 처음부터 지금까지 | 고정 개수 |

39.52초를 생성하면 마지막 창을 만들 때 어텐션이 직접 보는 것은 최근 8.32초뿐이고, 앞의 31.2초는 Mamba 상태와 PCM에만 남습니다. Mamba 상태는 어텐션이 읽는 토큰이 아니어서, PCM(persistent content memory)이 이를 요약해 어텐션이 키와 값으로 읽는 슬롯에 옮겨 적습니다.

PCM 갱신 식은 다음과 같습니다(식 12).

`w_t = η·σ(f_w([j_t; P_{t−1}])),  P_t = (1 − w_t)⊙P_{t−1} + w_t⊙Z_t`

`Z_t`는 이번 창에서 쓸 새 내용으로, Mamba 상태를 풀링한 값, 지난 창 대비 상태 변화량, 텍스트 지시 임베딩을 합쳐 만듭니다(식 8~11). `w_t`는 얼마나 덮어쓸지를 정하는 게이트이고, `η`는 그 상한입니다(부록 B에서 0.25). 한 창이 기억을 통째로 갈아엎지 못하게 막습니다.

가상의 숫자로 보면, 매 창 게이트가 상한인 0.25로 열리면 첫 창의 내용은 19개 창 뒤에 `0.75^19 ≈ 0.004`만 남습니다. 게이트가 0.05로 작게 열리면 `0.95^19 ≈ 0.38`이 남습니다. 게이트가 기존 슬롯까지 보고 열림 정도를 정하는 이유입니다.

읽기 쪽은 기존 어텐션 출력 `A_0`와 슬롯을 포함한 출력 `A_P`를 섞습니다(IV-C절). `Y = A_0 + tanh(ρ)·(A_P − A_0) + σ(ζ)·M`에서 `ρ`를 0으로 초기화하므로, 학습 초기에는 PCM이 없는 모델과 출력이 정확히 같습니다. `M`은 Mamba 분기 출력입니다.

### 확정된 창만 기억에 쓴다

가장 실용적인 규칙입니다(IV-C절, 알고리즘 1). 창 하나를 만들려면 DDIM 10단계와 가이던스 분기 3개 때문에 루트와 몸통 모델을 각각 30번씩 호출합니다. 호출마다 Mamba 상태를 갱신하면, 같은 2초를 만드는 도중의 후보 30개가 각 모델의 기억에 마치 이어지는 시간처럼 쌓입니다. 이 후보들은 연속된 순간이 아니라 같은 창의 대안일 뿐입니다.

그래서 노이즈 제거 중에는 기억을 얼린 스냅숏만 읽고, 완성된 창으로 깨끗한 패스를 한 번 더 돌려 캐시, Mamba 상태, PCM을 한꺼번에 갱신합니다.

```python
for t in range(num_windows):
    mem_read = memory.snapshot()              # 읽기 전용
    z = randn(window_shape)
    for tau in reversed(range(K)):            # DDIM 10단계
        outs = []
        for cond in (text, spatial, empty):   # CFG 분기 3개
            r = root_net(z, cond, mem_read)
            b = body_net(z, cond, local(r), mem_read)
            outs.append(concat(r, b))
        z = ddim_step(z, cfg_combine(outs), tau)
    x = recenter(z)
    proposal = clean_pass(x, mem_read)        # 캐시/상태/슬롯 후보
    if valid(proposal):
        memory = proposal                     # 루트와 몸통을 함께 커밋
        emit(decode(x))
```

## 실험 결과

모든 비교 모델을 같은 G1 데이터(약 15.7만 개 기록)로 10만 번씩 다시 학습시켰습니다(V-A절, 부록 C-B). Root CE와 End CE는 마감 시각의 루트와 손목 또는 발목의 목표 오차(cm, 낮을수록 좋음), Cmd.는 지시한 이동 상태와 일치한 프레임 비율입니다.

### 긴 생성

HiPHI 39.52초(19개 창) 결과 일부입니다(표 1).

| 모델 | Root CE | End CE | Cmd. (%) | 창당 지연(ms) |
|---|---|---|---|---|
| DartControl | 291.58 | 295.86 | 40.32 | 28.2 |
| Motion Mamba(1편) | 125.74 | 130.17 | 25.77 | 310.5 |
| ARDY | 10.09 | 14.84 | 23.53 | 105.1 |
| MotionStreamer | 7.78 | 21.67 | 18.85 | 159.8 |
| **Motion Mamba 2.0** | **7.55** | **13.64** | **46.05** | 333.4 |

짧은 생성에서 강하던 모델 상당수가 길게 가면 수 미터씩 빗나갑니다. Root CE는 MotionStreamer와 3% 차이지만, End CE와 Cmd.에서는 격차가 뚜렷합니다.

### 무엇이 효과를 냈나

같은 HiPHI 39.52초에서 기억 장치를 하나씩 빼 봤습니다(표 4).

| 변형 | Root CE | End CE | Cmd. (%) |
|---|---|---|---|
| Mamba 없음 | 60.00 | 64.86 | 35.27 |
| Mamba만 | 9.36 | 15.54 | 32.20 |
| PCM, 텍스트 조건 제외 | 8.62 | 14.62 | 33.34 |
| PCM, 상태 변화량 제외 | 8.30 | 14.18 | 32.65 |
| 전체 | 7.55 | 13.64 | 46.05 |

Mamba를 넣는 것만으로 Root CE가 84% 줄었습니다. PCM은 Root CE를 19% 더 줄였고 Cmd.를 크게 올렸습니다.

### 속도와 실제 로봇

RTX 4090에서 창 하나의 중앙값 지연은 1685.35ms에서 276.14ms로 줄었습니다(표 7). 대부분 CUDA Graph 재생 덕분이며, 호스트의 커널 실행 요청이 93.4% 줄었습니다. 6.138배는 짝지은 측정의 비율 중앙값이고, 두 중앙값을 나누면 약 6.10배입니다. 시드를 고정한 100창 생성 4번에서 출력은 최적화 전과 비트 단위로 같았다고 합니다.

실제 G1(VI절, 표 8)에서는 원격 GPU 서버가 동작을 생성하고, 로봇의 기존 추종 제어기 SONIC이 따라갑니다. 네 과제 100번 시도에서 94번을 끝까지 해냈고 넘어진 적은 없었습니다.

## 한계

저자가 VII절에서 밝힌 한계는 물체를 다루는 동작을 지원하지 않는 점입니다. 본문 곳곳에서 다음도 인정합니다.

- **학습과 추론의 간극**: 학습 때는 정답 동작을 최대 196프레임까지만 과거로 넣습니다. 자기가 만든 긴 과거에서 기억을 꺼내 쓰는 일은 직접 학습하지 않았습니다(부록 B-A, C-B).
- **기억의 정확도**: 고정 크기 기억이라 아주 오래된 사건을 그대로 되살린다고 주장하지는 않습니다.
- **속도**: 창당 약 270~330ms로 2.08초 창보다는 빠르지만, DartControl(약 28~39ms)보다 열 배 안팎 느립니다(표 1~3).

덧붙여, 로봇 실험에는 비교 모델이 없고 균형은 모델이 아니라 SONIC이 책임집니다.

## 실무에서 가져갈 점

- **상태 있는 모델은 후보와 확정을 나누세요.** 빔 서치나 추측 디코딩처럼 같은 구간의 후보를 여러 번 만드는 곳에서는 KV 캐시나 순환 상태를 확정된 결과로만 갱신해야 합니다. 후보마다 상태를 갱신하는 것은 직접 구현할 때 흔한 실수입니다.
- **새 모듈은 0에서 시작하는 게이트로 붙이세요.** 이 논문처럼 `ρ`를 0으로 초기화하면 기존 동작을 깨지 않고 새 경로를 더할 수 있습니다.
- **작은 배치 추론은 CUDA Graph부터 보세요.** 이 논문에서 커널 융합의 추가 이득은 약 3%였고, 대부분은 커널 실행 요청 오버헤드를 없앤 데서 나왔습니다.
