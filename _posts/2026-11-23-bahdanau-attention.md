## 한 줄 요약

번역 모델이 원문 전체를 고정 길이 벡터 하나로 압축하던 방식을 버리고, 번역문의 단어를 하나 만들 때마다 원문의 어느 부분을 볼지 스스로 고르게 했습니다. 어텐션이 처음 등장한 논문이며, 긴 문장에서 번역 품질이 무너지던 문제를 풀었습니다.

## 배경: 어떤 문제를 풀려는가

이 글은 커리큘럼 공통 기초 트랙의 세 번째 글입니다. 앞의 두 글과는 독립적으로 읽을 수 있고, 뒤의 Transformer 글을 읽기 전에 필요합니다.

당시 신경망 번역은 인코더-디코더 구조였습니다.

1. 인코더 RNN이 원문을 한 단어씩 읽으며 은닉 상태를 갱신합니다.
2. 마지막 은닉 상태가 문장 전체의 요약 벡터가 됩니다.
3. 디코더 RNN이 그 벡터 하나만 보고 번역문을 한 단어씩 만듭니다.

문제는 2번입니다. 다섯 단어짜리 문장이든 쉰 단어짜리 문장이든 같은 크기의 벡터에 모든 정보를 담아야 합니다. 사람에 빗대면, 긴 문단을 한 번 읽고 책을 덮은 뒤 기억만으로 번역하는 것과 같습니다.

저자들은 이 고정 길이 벡터가 병목이라고 보았습니다. 근거로 든 것은 기본 인코더-디코더의 성능이 입력 문장이 길어질수록 급격히 떨어진다는 선행 연구입니다(1절).

## 핵심 아이디어

책을 덮지 않고 번역하게 합니다. 원문을 벡터 하나로 줄이지 않고 단어마다 벡터를 하나씩 남겨 두고, 디코더가 단어를 만들 때마다 그 벡터들을 다시 들여다봅니다(3절).

### 1. 단어별 표현을 만든다

인코더는 양방향 RNN입니다(3.2절). 문장을 앞에서 뒤로 읽는 RNN과 뒤에서 앞으로 읽는 RNN을 따로 돌리고, 같은 위치의 두 은닉 상태를 이어 붙입니다. 그러면 각 단어의 벡터가 그 단어 앞쪽의 문맥과 뒤쪽의 문맥을 모두 담게 됩니다. 논문은 이 벡터를 주석(annotation)이라고 부릅니다.

뒤쪽 문맥이 필요한 이유는 간단한 예로 알 수 있습니다. 영어의 "bank"가 은행인지 강둑인지는 뒤에 오는 단어를 봐야 정해지는 경우가 많습니다. 앞에서부터만 읽은 RNN은 "bank"의 위치에서 아직 그 정보를 갖고 있지 않습니다. 디코더가 이 단어를 들여다볼 때 제대로 된 정보를 얻으려면 벡터에 양쪽 문맥이 모두 들어 있어야 합니다. RNN은 가까운 입력을 더 잘 기억하므로, 각 주석은 자연스럽게 해당 단어 주변에 초점이 맞춰집니다.

### 2. 관련도 점수를 매긴다

디코더가 i번째 단어를 만들려는 시점에, 디코더의 직전 상태와 원문의 j번째 단어 벡터를 작은 순방향 신경망에 넣어 점수를 하나 받습니다. "지금 만들려는 단어와 원문의 j번째 단어가 얼마나 관련 있는가"를 묻는 것입니다. 이 신경망이 정렬 모델입니다(3.1절).

두 벡터를 각각 선형 변환해 더한 뒤 은닉층 하나를 통과시키는 방식이라, 나중에 Transformer 논문은 이것을 가산(additive) 어텐션이라고 불러 자신들의 내적 방식과 구분했습니다. 원문 단어 하나마다 이 신경망을 한 번씩 돌려야 한다는 점을 기억해 두면 뒤의 한계를 이해하기 쉽습니다.

### 3. 가중치로 바꿔 섞는다

원문의 모든 단어에 대해 점수를 구한 뒤 소프트맥스를 적용해 합이 1인 가중치로 바꿉니다. 그리고 단어 벡터들을 이 가중치로 더한 것이 그 시점의 문맥 벡터입니다.

가상의 숫자로 따라가 보겠습니다. 원문이 세 단어이고 정렬 모델이 낸 점수가 2.0, 1.0, 0.1이라고 합시다.

| 원문 단어 | 점수 | 소프트맥스 가중치 |
|---|---|---|
| 첫째 | 2.0 | 0.66 |
| 둘째 | 1.0 | 0.24 |
| 셋째 | 0.1 | 0.10 |

문맥 벡터는 `0.66 × h1 + 0.24 × h2 + 0.10 × h3`입니다. 첫째 단어의 정보가 3분의 2쯤 들어가고 나머지가 조금씩 섞입니다. 다음 단어를 만들 때는 디코더의 상태가 달라졌으므로 점수도 달라지고, 다른 단어에 무게가 실립니다.

### 4. 단어를 생성한다

디코더는 직전에 만든 단어, 자신의 은닉 상태, 방금 만든 문맥 벡터를 보고 다음 단어를 고릅니다. 기존 방식에서는 문맥 벡터가 문장 내내 하나로 고정이었지만, 여기서는 단어마다 새로 계산됩니다.

디코더의 한 스텝을 의사 코드로 쓰면 다음과 같습니다.

```python
# annotations: 원문 단어별 벡터 (길이 T)
scores = [align(s_prev, h_j) for h_j in annotations]   # 정렬 모델
weights = softmax(scores)                               # 합이 1
context = sum(w * h_j for w, h_j in zip(weights, annotations))

s = rnn_step(s_prev, y_prev, context)                   # 디코더 상태 갱신
y = predict_word(y_prev, s, context)                    # 다음 단어
```

### 기존 방식과 나란히 놓고 보면

| | 기존 인코더-디코더 | 이 논문 |
|---|---|---|
| 인코더가 넘기는 것 | 벡터 하나 | 단어마다 벡터 하나 |
| 문맥 벡터 | 문장 내내 고정 | 출력 단어마다 새로 계산 |
| 긴 문장 | 정보가 넘쳐 손실 | 필요한 부분만 골라 봄 |
| 인코더 | 한 방향 RNN | 양방향 RNN |

인코더의 부담이 달라졌다는 점이 중요합니다. 더는 문장 전체를 벡터 하나에 눌러 담을 필요가 없고, 각 단어 주변의 정보만 잘 정리해 두면 됩니다. 어디를 볼지는 디코더가 정합니다.

### 왜 "함께" 학습한다고 하는가

논문 제목의 요점은 정렬과 번역을 함께 배운다는 것입니다. 전통적인 통계 번역에서는 어느 단어가 어느 단어에 대응하는지를 별도의 단계로 구했습니다. 여기서는 가중치가 0과 1 사이의 연속값이라 전 과정이 미분 가능하고, 정렬 모델에도 번역 오차의 기울기가 그대로 흘러갑니다. 대응 관계에 대한 정답을 따로 주지 않아도 번역을 잘하려다 보면 정렬이 저절로 학습됩니다.

## 실험 결과

WMT'14 영어-프랑스어 번역으로 실험했습니다(4절).

| 항목 | 설정 |
|---|---|
| 학습 데이터 | 3억 4,800만 단어 |
| 어휘 | 언어별로 자주 쓰이는 3만 단어, 나머지는 모르는 단어로 처리 |
| 은닉 유닛 | 인코더와 디코더 각 1,000개 |
| 학습 | Adadelta, 미니배치 80문장, 모델당 약 5일 |
| 테스트 | 3,003문장, 빔 서치로 번역 |

기존 방식을 RNNencdec, 제안한 방식을 RNNsearch라고 부르며, 뒤의 숫자는 학습에 쓴 문장의 최대 길이입니다.

| 모델 | BLEU (전체) | BLEU (모르는 단어 없는 문장) |
|---|---|---|
| RNNencdec-30 | 13.93 | 24.19 |
| RNNencdec-50 | 17.82 | 26.71 |
| RNNsearch-30 | 21.50 | 31.44 |
| RNNsearch-50 | 26.75 | 34.16 |
| RNNsearch-50 (더 오래 학습) | 28.45 | 36.15 |
| Moses (통계 기반) | 33.30 | 35.63 |

표 1의 수치입니다.

- **같은 조건에서 크게 앞섭니다.** 최대 길이 30에서 7.57점, 50에서 8.93점 차이입니다.
- **짧은 문장만 보고도 이깁니다.** 30단어 이하 문장으로만 학습한 RNNsearch-30이 50단어까지 학습한 RNNencdec-50보다 높습니다.
- **통계 기반 시스템과 견줄 만합니다.** 모르는 단어가 없는 문장만 보면, 오래 학습한 RNNsearch-50이 Moses를 넘습니다. Moses는 4억 1,800만 단어의 단일 언어 말뭉치를 추가로 썼습니다.
- **긴 문장에서 무너지지 않습니다.** 기존 방식은 문장이 길어질수록 점수가 급락하지만, RNNsearch-50은 50단어가 넘어도 성능이 떨어지지 않았습니다(그림 2). 병목 가설을 직접 확인한 결과입니다.

가중치를 그림으로 그려 본 결과도 흥미롭습니다(그림 3).

- 영어와 프랑스어는 어순이 비슷해서 가중치가 대체로 대각선을 따라 순서대로 나타납니다.
- 형용사와 명사의 순서가 뒤바뀌는 곳에서는 대응도 그에 맞게 엇갈립니다. "European Economic Area"를 번역할 때 모델은 두 단어를 건너뛰어 "Area"를 먼저 보고 "zone"을 만듭니다.
- 한 단어가 여러 단어에 걸쳐 대응하는 경우도 부드럽게 처리합니다. "the man"을 "l'homme"로 옮길 때 두 단어를 함께 봅니다.

## 한계

저자들이 밝힌 한계 두 가지와, 읽으면서 보인 점 하나입니다.

- **계산량이 늘어납니다.** 번역문의 단어 하나를 만들 때마다 원문의 모든 단어에 대해 가중치를 계산합니다. 원문 길이와 번역문 길이를 곱한 만큼의 계산입니다. 원문과 번역문이 30단어씩이면 정렬 모델을 900번 돌리지만, 300단어씩이면 9만 번입니다. 15~40단어 수준의 번역에서는 심각하지 않지만 다른 과제에 적용할 때는 제약이 될 수 있다고 적었습니다(6.1절).
- **여전히 순서대로 계산합니다.** 논문이 한계로 꼽은 것은 아니지만, 인코더와 디코더가 모두 RNN이라 단어를 하나씩 차례로 처리해야 합니다. 모델 하나를 학습하는 데 약 5일이 걸렸습니다.
- **모르는 단어와 드문 단어를 잘 다루지 못합니다.** 어휘를 3만 단어로 제한했기 때문에 그 밖의 단어는 번역할 수 없습니다. 저자들은 이것을 앞으로 풀어야 할 과제로 꼽았습니다(결론).

모르는 단어 문제는 이듬해 단어를 더 작은 조각으로 쪼개는 서브워드 방식(BPE)이 나오면서 크게 완화됐습니다. 자주 쓰이는 조각들로 어휘를 구성하면 처음 보는 단어도 아는 조각들의 조합으로 표현할 수 있습니다. 순서대로 계산해야 하는 문제는 2017년의 Transformer가 RNN을 아예 걷어 내고 어텐션만 남기면서 풀었습니다. 이 트랙의 마지막 글에서 다룹니다.

## 실무에서 가져갈 점

- **병목을 의심하세요.** 모든 정보를 고정 크기 하나에 담게 하는 구조는 입력이 길어지면 무너집니다. 필요한 순간에 필요한 부분을 다시 찾아보게 하는 것이 어텐션의 출발점입니다.
- **어텐션은 "부드러운 조회"입니다.** 여러 후보에 점수를 매기고, 가중치로 바꿔 섞는다는 세 단계는 이후의 모든 어텐션에 그대로 남아 있습니다. 바뀐 것은 점수를 매기는 방법뿐입니다.
- **지금의 Transformer에 그대로 남아 있습니다.** 디코더가 인코더의 출력을 들여다보는 어텐션 층이 이 논문 구조의 직계입니다.
- **가중치는 들여다볼 수 있습니다.** 논문이 그림 3에서 한 것처럼, 모델이 출력의 각 부분을 만들 때 입력의 어디에 가중치를 두었는지 그려 볼 수 있습니다.
